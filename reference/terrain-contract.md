# ภูมิประเทศ FABDEM แบบ 2D และ 3D ในเว็บศิลา

Revision 1.6 ปรับใน 1.8 (ขยายความสูง สีความสูง เส้นชั้นความสูง) และ 1.9 (เขียนฉาก 3D ใหม่ด้วย MapLibre terrain แบบ CityMETER ทิศเหนือขึ้นเสมอ ค่าเริ่มต้น 2 เท่า) · สัญญาข้อมูลและการแสดงผล ผลตรวจหน้าจอและผลเผยแพร่ใช้หลักฐานแยก

ปุ่ม **2D / 3D** เหนือแผนที่สลับมุมมองในหน้าเว็บศิลาได้โดยตรง ทั้งสองมุมมองใช้ FABDEM V1-2 ข้อมูลที่ใช้วัดและระบายสีจำกัดเฉพาะ **อำเภอเมืองขอนแก่น รหัส 4001** ไม่ต้องเปิด CityMETER อีกแท็บ พื้นที่สรุปที่ผู้ใช้เลือกยังเป็นเทศบาล หมู่บ้าน หรือเขตเลือกตั้งเดิม ไม่เปลี่ยนตัวหารตามการเลื่อนกล้อง

[เปิด 2D](https://montri-th.github.io/sila/?dataset=terrain&mode=2d&lang=th) · [เปิด 3D](https://montri-th.github.io/sila/?dataset=terrain&mode=3d&lang=th)

## การใช้งานและสถานะ

- URL เก็บ `mode=2d|3d` สำหรับชุดภูมิประเทศเท่านั้น ค่าอื่นหรือชุดข้อมูลอื่นใช้ 2D รองรับการเปิดลิงก์ตรงและประวัติย้อนกลับ/เดินหน้า
- เมื่อสลับ รับศูนย์กลางและระดับซูมจากแผนที่เดิม เมื่อกลับ 2D ส่งมุมมองกลับให้แผนที่เดิม; เก็บมุมเอียงที่ใช้ใน 3D เพื่อกลับมาใช้ต่อ **ทิศเหนืออยู่ด้านบนเสมอ** (เจ้าของงานกำหนด 20 ต.ค. 2569) เอียงได้ด้วยคลิกขวาลากขึ้นลง Ctrl+ลาก ลากสองนิ้วขึ้นลง หรือ Shift+ลูกศรขึ้นลง แต่หมุนไม่ได้ และไม่มีเข็มทิศ
- แยกสถานะความสูงกับพื้นหลังถนน/ดาวเทียมตามการโหลดจริง พื้นผิวอาจพร้อมก่อนภาพพื้นหลังครบ ไม่ใช้สถานะ mesh ready ยืนยันว่า basemap พร้อม
- ระหว่างโหลด 3D ยังเห็นแผนที่ 2D เมื่อโหลดพื้นผิวสำเร็จจึงเปลี่ยนมุมมอง ถ้า WebGL หรือข้อมูลที่จำเป็นล้มเหลว ให้กลับ 2D พร้อมข้อความและปุ่มลองใหม่ ไม่เติมข้อมูลความสูงด้วยศูนย์
- 3D แสดงภูมิประเทศและเส้นขอบเขตประเภทที่เลือกเพียงประเภทเดียว คงการปิดทึบแบบโปร่งบางนอกเขตเทศบาลตามธีม การดูรายละเอียดรายการและชั้น GIS ประกอบใช้ใน 2D; ไม่วางเวกเตอร์แบนของ Leaflet ทับฉากเอียงหรือสร้างความสูงอาคารขึ้นเอง

## วิธีสร้างพื้นผิว 3D (revision 1.9)

แผนที่ 2D ใช้ Leaflet; ฉาก 3D ใช้ MapLibre GL JS 6.12.0 ที่อยู่ใน repository ระดับซูมของสอง engine ต่างกันหนึ่งขั้น: Leaflet 8–22 เท่ากับ MapLibre 7–21 การแปลงกล้องทำที่ขอบ API ของ module

Revision 1.9 เปลี่ยนวิธีวาดตามตัวดูภูมิประเทศ CityMETER: ให้ MapLibre วาดพื้นผิวเองด้วย terrain แบบ raster-dem ซึ่งมี mesh ลดรายละเอียดตามระยะ (level of detail) และฉายภาพพื้นหลังถนน/ดาวเทียม สีความสูง เงา เส้นชั้นความสูง และเส้นขอบลงบนผิว tile ทั้งหมดมาจาก Web Worker (`terrain-dem-worker.js`) ผ่าน protocol ของหน้าเว็บเอง งานถอดรหัส tile การประมาณค่าเพิ่ม การวาดเงา และการสร้างเส้นชั้นความสูงจึงไม่อยู่บน main thread ฉากเดิม (1.6–1.8) วาด mesh เอง 257 × 257 จุดต่อ tile (ราว 1.1 ล้านสามเหลี่ยมในมุมมองเริ่มต้น) คัดลอกภาพทั้งเฟรมเป็น texture ทุกเฟรม และถอดรหัส tile บน main thread จึงกระตุก

- **พื้นผิวและเงา** ใช้ค่า FABDEM จากบริการ tile เดิม (ครอบคลุมทั้งประเทศ) ต่อออกนอกอำเภอเท่าที่มองเห็น เพื่อไม่ให้เกิดหน้าผาปลอมที่ขอบอำเภอ เพราะเขตเทศบาลห่างขอบอำเภอเพียงราว 50 ม. ทางเหนือ ช่องไม่มีข้อมูล (alpha 0) ในพื้นผิวเติมด้วยค่าเฉลี่ยของเพื่อนบ้านที่วัดได้เพื่อไม่ให้เกิดผนังที่ศูนย์ นอกเขตบริการ FABDEM (นอกประเทศ เห็นได้เฉพาะใกล้เส้นขอบฟ้า) ผิวคงที่ที่ค่าเฉลี่ยของ tile ที่โหลดแล้ว ช่องที่เติมเหล่านี้ไม่ถูกระบายสี ไม่มีเส้นชั้นความสูง และไม่ถูกวัด
- เหนือ native zoom 12 ประมาณค่าเพิ่มถึง zoom 14 ด้วย Catmull-Rom แบบจำกัดค่าไม่เกินสี่จุดรอบข้าง (แบบเดียวกับ CityMETER) ผิวจึงโค้งเรียบแทนเหลี่ยม แต่ไม่เพิ่มรายละเอียดจริงจากข้อมูลราว 30 ม.
- **สีความสูง เส้นชั้นความสูง และการวัดความต่างระดับ** ใช้ FABDEM ที่วัดได้จริงเฉพาะ pixel ที่อยู่ในอำเภอทั้ง pixel pixel ที่เส้นขอบผ่านหรือไม่มีข้อมูลเขียนเป็น −9999 และวาดโปร่ง (ไม่ใช่ศูนย์) เส้นชั้นความสูงสร้างจากค่าเหล่านี้ด้วย maplibre-contour 0.1.1 (BSD-3) cell ที่มีมุมไม่มีข้อมูลไม่สร้างเส้น
- **เงา** วาดใน worker ด้วยกฎเดียวกับเงา 2D (แสงจากทิศตะวันตกเฉียงเหนือ มุม 45°) ใช้ค่าเพื่อนบ้านจริงข้ามขอบ tile จึงไม่มีรอยต่อ ความชันคูณตัวคูณที่เป็นกำลังสองใกล้ค่าขยายความสูง (1, 2, 4 … 64) เงาจึงตามรูปทรงที่ขยายแล้วแบบ 1.8 และเปลี่ยน tile เงาเฉพาะเมื่อข้ามขั้น
- เส้นขอบเขตและการปิดทึบโปร่งบางนอกเขตเทศบาลวาดบนผิว ท้องฟ้าและขอบฟ้าใช้สีพื้นของธีม หมอกเริ่มที่ขอบฟ้าเท่านั้น สีความสูงจึงคง HEX เดิม
- จอความละเอียดสูงวาดไม่เกิน 2 pixel ต่อ pixel CSS และใช้ MSAA เฉพาะจอความละเอียดต่ำ เพื่อให้แต่ละเฟรมเบา tile เงาไม่ดึงทั้ง tile เพื่อนบ้านเพียงเพื่อหนึ่งแถว pixel ที่ขอบมุมมอง

ผลวัดในเครื่องทดสอบ (Chromium headless ที่ใช้ GPU จำลองด้วย CPU ท่าเดิม 3 วินาที: ลากซ้ายเลื่อน 1.5 วินาที แล้วลากขวา 1.5 วินาที): ฉาก 1.8 (ภาพ 640 × 408 ขยายอัตโนมัติ 40 เท่า) ใช้เวลาประมวลผล 268 วินาที long task 114 ครั้ง · ฉาก 1.9 ค่าเริ่มต้น 2 เท่า ใช้ 4.1 วินาที ไม่มี long task frame กลาง 16.7 มิลลิวินาที · โหมดอัตโนมัติ (40–50 เท่า) 4.1 วินาที long task 2 ครั้ง รวม 237 มิลลิวินาที · ภาพใหญ่ 960 × 728 ใช้ 3.3 วินาที long task 1 ครั้ง 66 มิลลิวินาที ทิศเหนือยังอยู่ด้านบนหลังลากขวาทุกครั้ง CityMETER ที่เผยแพร่จริงวัดด้วยท่าเดียวกัน (ภาพ 1280 × 800 คนละหน้า) มี long task 9 ครั้ง รวม 857 มิลลิวินาที ใช้เป็นข้อมูลประกอบ ไม่ใช่การเทียบตรง ตัวเลขเหล่านี้เทียบกันในเครื่องเดียวกันเท่านั้น ไม่ใช่อัตราเฟรมบนโทรศัพท์หรือ GPU จริง ซึ่งยังไม่ได้วัด ([ผลวัด 1.9](../qa/revision-1.9-terrain3d-benchmark.json))

## ขยายความสูง (revision 1.8, ค่าเริ่มต้นเปลี่ยนใน 1.9)

ใช้แบบเดียวกับตัวดูภูมิประเทศ CityMETER: แถบเลื่อนแบบลอการิทึม 0.5–50 เท่า ค่าต่ำกว่า 10 แสดงทศนิยมหนึ่งตำแหน่ง และโหมดอัตโนมัติที่ทำให้ความต่างระดับในมุมมอง (เปอร์เซ็นไทล์ 99 ลบ 1 ของความสูงที่วัดได้บนตาราง 24 × 24 จุด วัดใน worker) สูงเป็นสัดส่วนหนึ่งของความกว้างภาพ ค่าเริ่ม 15% ปรับได้ 5–30% จุดที่ไม่มีข้อมูลข้ามไป ไม่ถือเป็นศูนย์ ถ้าความต่างระดับน้อยกว่า 0.5 ม. ไม่คำนวณค่าอัตโนมัติ และเปลี่ยนค่าเมื่อต่างจากเดิมเกิน 5% เท่านั้น

ค่าเริ่มต้นตั้งแต่ revision 1.9 คือ **2 เท่าแบบกำหนดเอง** ตามที่เจ้าของงานกำหนด (20 ต.ค. 2569) ศิลาค่อนข้างราบ ทั้งเขตเทศบาลสูงต่างกันราว 60 ม. ในความกว้างราว 13 กม. ภาพที่ 2 เท่าจึงค่อนข้างแบน ถ้าต้องการรูปทรงชัดขึ้นเลือกโหมดอัตโนมัติ (มุมมองเริ่มต้นขยายราว 38–40 เท่า ขึ้นกับขนาดภาพ) URL เก็บ `ex=<ค่า>` เมื่อไม่ใช่ 2 เท่า `ex=auto` สำหรับโหมดอัตโนมัติ และ `ext` สำหรับสัดส่วนที่ไม่ใช่ 15% ลิงก์เก่าที่มีแต่ `ext` ยังเปิดโหมดอัตโนมัติ เส้นขอบวาดบนผิวที่ขยายแล้ว ความสูงที่ขยายใช้ดูรูปทรงเท่านั้น ไม่ใช่ความสูงจริงหรือระดับน้ำ

## สีความสูงและเส้นชั้นความสูง (revision 1.8)

- สีความสูง 6 ชุดจาก OH3 ตามที่เจ้าของงานขอ ค่าเริ่มต้น "ธรรมชาติ ที่ราบ" (7 สีแรกของ OH3 relief ไม่มีสีเทาขาวของยอดเขา) ใช้ HEX เดียวกันทั้งธีมสว่างและมืด เป็นข้อยกเว้นของ LDS เฉพาะชั้นนี้ เพราะ LDS ไม่มีสเกลความสูงพื้นดิน ชุดสีและที่มาอยู่ใน [terrain-palettes.json](terrain-palettes.json)
- กระจายสีตามพื้นที่เป็นค่าเริ่มต้น (แต่ละช่วงสีครอบคลุมพื้นที่พอ ๆ กัน จาก quantile 101 ค่าของความสูงในมุมมอง) หรือตามเมตร ช่วงสียืดตามความสูงที่เห็นโดยตัดบนล่าง 0.5% หรือล็อกช่วงไว้เพื่อเทียบพื้นที่ แบ่งสีเป็นชั้นเท่าระยะเส้นได้
- เส้นชั้นความสูงเลือกได้ 0.05, 0.1, 0.2, 0.5, 1, 2, 5, 10 ม. ค่าเริ่ม "ละเอียดสุดที่อ่านได้" เลือกระยะที่เล็กที่สุดซึ่งเส้นในมุมมองไม่เกิน 100 เส้น (เพดาน 200) เส้นหนาทุก 5 เส้น ใน 2D เส้นรองจางลงเมื่อห่างกันไม่ถึงราว 10 พิกเซล CSS และหายที่ 4 พิกเซล เส้นหนาจางที่ 8 และหายที่ 3 พิกเซล ใน 3D (1.9) เส้นเป็น vector tile ที่ปรับความหนาตามระดับซูมแทนการจาง เส้นหนาระบุจากความสูงที่เป็นจำนวนเต็มของระยะเส้น จึงตรงทุกเส้นแม้ระยะ 0.05 ม. เมื่อเปิดสีความสูง เส้นใช้หมึกเข้มสีเดียวกันทั้งธีมสว่างและมืด เพราะสีความสูงเป็น HEX เดียวกันทั้งสองธีม เมื่อปิดสี (เงาอย่างเดียว) ธีมมืดวาดเส้นสีอ่อนที่ความเข้ม 70%
- ระยะเส้นที่ละเอียดกว่าราว 1 ม. ละเอียดกว่าความคลาดเคลื่อนของ FABDEM (MAE ราว 1.12 ม. ในพื้นที่สร้างแล้ว และ 2.88 ม. ในป่า ตามผลประเมินต้นทาง) ใช้ดูรูปทรงเท่านั้น หน้าเว็บบอกไว้ในคำอธิบายสัญลักษณ์

## แหล่งข้อมูลและข้อจำกัด

ต้นทาง `FABDEM V1-2`, tile build `z12-20261007`, Terrarium 256 px, native zoom 12, display zoom สูงสุด 22 รายละเอียดต้นทางประมาณ 1 arc-second (~30 ม.) การขยายจอไม่เพิ่มรายละเอียด วันสร้าง tile 7 ตุลาคม 2026 ไม่ใช่วันสำรวจ ฐานอ้างอิงแนวดิ่ง ความแม่นยำในพื้นที่ และวันสำรวจยังไม่ประกาศ

3D ช่วยอ่านลักษณะภูมิประเทศ ไม่ใช่ระดับน้ำ การพยากรณ์น้ำท่วม หรือผลสำรวจระดับเพื่อออกแบบก่อสร้าง แสงเงาและการเอียงไม่ใช่หลักฐานความเสี่ยง

ชั้นภูมิประเทศไม่เพิ่มไฟล์ใน `data/` (revision 1.9 เพิ่มเฉพาะ worker และ maplibre-contour ใน `vendor/maplibre-contour/` ซึ่งเป็นโค้ด ไม่ใช่ข้อมูล DEM) สถานะ terrain ใน catalog เดิมเป็น historical pending; consumer override เฉพาะหน่วยความจำเมื่อ metadata ภายนอกพร้อม ไม่มี raw DEM ใหม่ใน repository ไม่มีการส่งออกหรือเก็บ tile เป็นชุดข้อมูลบน host ของเว็บ
