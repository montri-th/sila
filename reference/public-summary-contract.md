# ข้อมูลสรุปเทศบาลรอบ 19 ตุลาคม 2569

สถานะ: ตรวจสัญญาข้อมูลและหน้าจอในเครื่องแล้ว ผลเผยแพร่ให้ยึด GitHub Pages commit/build และ live-byte receipt ของรอบที่ตรวจจริง แยกจากผลตรวจสัญญานี้

เพิ่มมุมมอง `tax`, `business`, `animals`, `healthservices` และ optional `caregroups` จาก `data/municipal-summary.json` โดยคงข้อมูล GIS 16 ชุดเดิม จุดสถานพยาบาล `health` เดิม 4 จุด และ default รูปอาคาร ไม่จับคู่ข้อมูลดูแลระยะยาวกับจุดสถานพยาบาลหรือหมุดบ้านโดยอนุมาน

มุมมองใหม่แสดงยอดและความพร้อมระดับเทศบาลเท่านั้น เมื่อเลือกหมู่บ้านหรือเขตเลือกตั้ง แผนที่กับ breadcrumb ยังเก็บบริบทที่เลือกไว้ แต่ยอดสรุปไม่เปลี่ยนและมีข้อความกำกับ ไม่มีการแสดงค่าไม่ทราบเป็นศูนย์หรือสร้างยอดย่อยตามพื้นที่ขึ้นมา

## สัญญาข้อมูล

- Schema: `sila-municipal-public-summary/1.0`
- `exposure`: `municipality_aggregate_only`
- `recordDetailsAvailable`: `false`
- `sourceRowExportAvailable`: `false`
- `datasets`: ต้องมีสี่ ID เดิม; เพิ่ม optional `caregroups` ได้เป็นชุดที่ห้า พร้อม `coverage: supplied_service_cohort_only` ซึ่งเป็นกลุ่มในบัญชีที่ได้รับ ไม่ใช่ผู้ป่วยทั้งหมดของเมือง
- Metric เก็บ `value` เป็นตัวเลขหรือ `null`, ชื่อ หน่วย หมายเหตุสองภาษา และ `sourceIds` ของชุดอ้างอิงสรุป ตัวเลขศูนย์ที่มีจริงแสดง `0`; ค่าที่ยังไม่ยืนยันแสดง `—` พร้อมคำอธิบาย หาก `state/status` เป็น suppressed/withheld/restricted/not_published ให้แสดงว่าไม่เผยข้อมูลส่วนนี้
- Source description มีชื่อที่เหมาะกับการเผยแพร่ ช่วงอ้างอิง สถานะตรวจ และ `publicDownload:false` ไม่มี raw Drive file link หรือดาวน์โหลดรายแถว
- วันรับไฟล์ไม่ใช่วันสำรวจ วันตัดยอด หรือปีภาษีของทุกบันทึก ต้องอ่านช่วงอ้างอิงและหมายเหตุข้างแต่ละ metric

ยอดรับในบัญชีชำระเป็นยอดตามช่วงรับเงินในต้นทาง อาจมีหลายปีภาษีและส่วนเพิ่ม ไม่เท่ากับยอดประเมินปีเดียวกัน ยอดลูกหนี้ หรือเงินที่โครงการทำให้เก็บเพิ่ม ห้ามสร้าง collection rate หรือผลเพิ่มจากส่วนต่างของตัวเลขเหล่านี้โดยยังไม่กระทบยอดรายการ

## พฤติกรรมหน้าเว็บ

`public-aggregate.js` ดูแลคำอธิบาย ภาพรวม ความพร้อม และแหล่งข้อมูล โดยใช้สีพื้น ฟอนต์ และไอคอนชุดเดิม รายการใหม่เข้าสู่เมนูโดยไม่แก้ geometry หรือ scope counts เดิม ภายในมุมมองใหม่ tab รายการเปลี่ยนชื่อเป็นความพร้อม ไม่มีรายละเอียดรายบุคคล ปุ่มส่งออก CSV รายแถว หรือ raw source link

ถ้าไฟล์สรุปเปิดไม่ได้หรือ exposure contract ไม่ถูกต้อง ชั้น GIS เดิมยังทำงาน และแสดงสถานะเปิดสรุปไม่สำเร็จ แทนการอ้างว่าไม่มีข้อมูลหรือแสดงตัวเลขศูนย์

การค้นข้อมูลเพิ่ม/เตรียมคำถาม AI ใช้เฉพาะชื่อชุดข้อมูลและพื้นที่สาธารณะตาม pattern เดิม ไม่แนบไฟล์ รายชื่อ รหัสใบประเมิน บ้าน พิกัด ผู้ป่วย หรือตัวเลขรายบุคคลโดยอัตโนมัติ

## ขอบเขต public และ Officer

Static website ไม่มีระบบจำกัดสิทธิจริง ป้าย Officer preview และการซ่อนไฟล์ไม่ใช่ authentication จึงเผยเฉพาะ payload สรุปที่ตรวจแล้ว ไม่คัดลอก raw XLSX/PDF/DBF, patient list, tax/debtor records หรือ restricted work queue ลง tree ที่เผยแพร่

รหัสจาก deterministic hash ของตัวตนแปลง ตำแหน่ง PDF หน้า/แถว หรือชุดเนื้อที่–ราคาต่อหน่วย–มูลค่าที่จำเพาะสามารถเชื่อมกลับไปยังเอกสารสิทธิได้ จึงไม่ใช้เป็นวิธีทำให้ชุดภาษีรายแปลงไม่ระบุตัวตนสำหรับเว็บนี้ และไม่ส่ง portfolio รายแปลงเข้าฝั่ง public

งานเจ้าหน้าที่ต้องอยู่ในช่องทางที่ยืนยันตัวตนและสิทธิหน่วยงานจริง โดย server บังคับ scope ของข้อมูล รายละเอียด คำค้น และ export รวมถึงการกระทบใบยกเลิก เลขประเมินซ้ำ การรับชำระ ส่วนเพิ่ม และตัวตนทรัพย์สินก่อนคำนวณยอดค้างหรือผลเพิ่มที่ยืนยันแล้ว

## การตรวจที่ต้องแนบกับการส่งมอบ

ตรวจ approved payload แยกจากผล UI: grain/ช่วงอ้างอิง/ตัวหาร/ข้อจำกัดต้องถูกต้องก่อนนำไปแสดงผล ต่อด้วย contract tests, actual render ไทยและอังกฤษ desktop/จอแคบ, null/zero/withheld, สลับขอบเขตโดยไม่เปลี่ยนยอดเทศบาล, ไม่มี row export, เก็บ dataset default และ all-house-points เดิม การตรวจ local ไม่เท่ากับ production deployment


## Revision1.5: กลุ่มผู้รับการดูแลและแบบภาษีเพิ่มเติม

GIS16เดิม + summary5 =21ชุดและภาพรวม หน้าเริ่มต้นยังเป็นรูปอาคาร ค้น “ผู้ป่วย” หรือ “กลุ่มเปราะบาง” เพื่อเปิด `caregroups` ได้ แยกจาก `healthservices` ที่เป็น inventory และ `health` จุดสถานพยาบาล4จุดเดิม ไม่สร้างหมุดผู้ป่วยหรือยอดย่อยตามหมู่บ้าน/ผู้ให้บริการ

194คือรหัสต้นทางไม่ซ้ำในชุดที่ได้รับ ยังไม่ยืนยันเป็น194บุคคลที่ตรวจตัวตนครบ รหัสกลุ่ม1–4ใช้ตามทะเบียนก่อน โดยคำอธิบายต้นฉบับกลุ่ม3/4เหมือนกัน คำ HT/DM/STROKE/DLP/CKD/CVA ซ้อนกันได้ ไม่ใช่วินิจฉัยที่รับรองหรือ prevalence ไม่รวม STROKE/CVA หรือรวมทุกคำเป็นคน หมวดที่เผยมีค่าอย่างน้อย10 ไม่เผยชื่อหมวดเล็ก ยอดคงเหลือหรือ cross-tab ที่ช่วยอนุมานรายบุคคล

Optional `breakdowns` เก็บตาราง `id`, `label`, `note` และ `rows` ที่ใช้สัญญา metric เดียวกัน ไม่บวกทุกแถวอัตโนมัติ ใช้หน่วยต้นทางและแยก unknown/withheld จากศูนย์

ภาษีมีไฟล์ใช้งาน10ไฟล์: ประเมิน/ชำระ/ลูกหนี้/ประกาศเดิม4 และแบบ1/2/3/4/7/8อีก6 แบบ7/8ในโฟลเดอร์ใหม่ส่งออกซ้ำที่ตรวจค่าพร้อมชนิดข้อมูล1,419,353ช่องแล้วตรงกับเดิม จึงนับครั้งเดียว ตาราง1/3/7และ2/4/8อธิบายทรัพย์สินที่ซ้อนชุดกัน ไม่ใช่ทรัพย์สินเพิ่ม3เท่า Candidate pairs ยังต้องทวนตัวตน/ปี/ใบประเมินที่มีผลก่อนคำนวณยอดภาษี

ภูมิประเทศเชื่อม FABDEM ผ่าน approved metadata และ moduleภายนอก โดยแก้ catalog entry เฉพาะในหน่วยความจำเป็น `ready_external_dem` เมื่อ metadata ทั้ง2ไฟล์เปิดได้ `data/catalog.json` เดิมยังเก็บสถานะ historical pending ไว้ byteเดิม ไม่ใช้สถานะเก่านั้นตัดสิน UI ปัจจุบัน ดู [terrain contract](terrain-contract.md)
